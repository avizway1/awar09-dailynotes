

Monolithic Architecture : Binds all software components together into a single, unified codebase. 
--> All or Nothing.. As it deployed as one single unit.
--> We choose one programing language and we develop the entire application.
--> Most of the cases, we need to scale the entire application.
--> Single centralised database for entire application.


Microservices Architecture: THis breaks the application into a collection of smaller, independent servcies that communicate over a network.
--> Each service is completely independent.
--> We can choose required programing languages per module. (frontend --> python, cart --> java, rating --> postgre, user management --> mysql) ==> polyglot.
--> we can scale services independently.. (more servers --> frontend, less servers --> cart)

Amazon : frontned, recommendation, cart, reviews, ratings, payment, address storage..

Restart polocies : We can control what happens when a container stops or the host reboots.

docker run -d --restart=always --name mynginx5 -p 80:80


always				: Always restart, Including on host reboot
unless-stopped		: Similar to always, but not if manually stopped.
no					: Never restart

Bridge Mode: 
--> Bridge mode will have its own IPs inside the docker network.
--> It required port mapping (-p 80:80 (or) -p 8888:80)
--> THis is more isolated and secured
--> Works on Linux, MacOs, Windows
--> This mode has a NAT component, that helps to resolve container's IP. One additional HOP involved in traffic flow. 
--> best for Enterprise grade / Multi COntianer applications.

HOST Mode : 
--> Share host's IP and Port.
--> Port mappinf not required.
--> Less isolated compared to bridge, as it uses host network.
--> Works only in Linux OS.
--> Slightly faster comapred to bridge, as no NAT involved.
--> We can use this for System level tools i.e; monitoring agents.
